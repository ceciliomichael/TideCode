# tools.patch

Through exec: `{"code":"return await tools.patch({ patch: payloads.patchText });","payloads":{"patchText":"*** Begin Patch\n*** Update File: src/example.ts\n@@\n-const offset = 6\n+const offset = 8\n*** End Patch"}}`. Obtain the tool contract first. Exec recovers misplaced top-level strings, exact bare payload bindings, and unique case/underscore/hyphen name variations; conflicting values and ambiguous aliases reject. Patch syntax, permissions, and source-context validation still apply.

Each `@@` starts a hunk and must be followed by its context, additions, or removals. It does not close a hunk. Continue directly with the next file header or `*** End Patch` after the last body line. A single bare trailing `@@` immediately before either boundary is tolerated only after an actual edit in that file; empty first/interior hunks and empty headers carrying context or line numbers remain errors. Empty-hunk diagnostics identify the file and patch line so you can correct the patch before retrying.

Apply an atomic raw Codex patch. Read exact source before constructing a patch. Use complete source lines in contextual hunks, order hunks top-to-bottom, and include a distinctive `@@` context or appropriate line position when similar blocks repeat. The matcher normalizes line endings and supports contextual whitespace differences, but do not rely on fuzzy matching to select ambiguous blocks. Updates preserve source line endings and UTF-8 BOM. All hunks are staged before writing and recoverable failures roll back committed files. If a hunk fails, reread the reported source lines and reconstruct the failed hunk; do not repeatedly submit the same invalid patch. Put literal multiline patch text in outer `exec.payloads` and pass its payload reference as `patch`. Preserve source backticks and interpolation expressions as data; do not wrap the raw patch in a JavaScript template literal or String.raw. In Plan Mode, edits are restricted to the active plan.
