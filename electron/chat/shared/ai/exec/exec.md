# TideCode exec

Execute a TideCode-owned, restricted JavaScript-like program. The only injected host authority is the exact documented `tools.*` registry. This is not Node.js; do not import modules, use process/require, access raw filesystem or network APIs, or invent capabilities.

Await every `tools.*` call. Use `try/catch` to recover from an expected failure, not `.catch()` on a tool promise. Return concise JSON-compatible values; tool outputs are bounded. Use independent concurrent calls only when there is no data or mutation dependency. Unsupported syntax and unknown APIs fail explicitly; inspect errors rather than guessing replacements.

Prefer `tools.available.list({ namespace: "native" })` (default) for native tools. `tools.available.list({ namespace: "mcp" })` lists MCP server namespaces; `tools.available.list({ namespace: "github", page: 1 })` lists one server's tools, ten names per page. Use `tools.available.search({ namespace: "github", query: "issue" })` for targeted server-specific discovery. Before first execution retrieve the exact authorized contract with `tools.available.get({ name })`. Known exact native names may be retrieved directly without listing; MCP names require discovery via list or search before get. List and search return names only; get returns Markdown instructions and typed parameters. The host remembers obtained contracts for the current chat and mode. If an authorized call is attempted before get, the host retrieves its contract for retry. MCP success returns decoded payload, not a normal native `ToolResult`.

Paths are workspace relative unless using an explicitly supported alias. `@workspace/...` is the bound workspace, `@attachments/...`, `@skills/...`, and `@tool-output/...` are read-only aliases. Never guess an unobserved child path; use list/glob/grep first. Inspect attachments before relying on their contents. Large results provide exact continuation or `@tool-output/...` paths: use those rather than restarting wide reads.

User-selected mentions use `[[tool:target]]` markers. `[[tools.read:path]]` requests reading that exact file or image with `tools.read({ path })`; `[[tools.list:path]]` requests listing that exact folder with `tools.list({ path })`. Preserve the full workspace or attachment alias inside the marker. `[[tools.skill.load:name]]` requests loading the exact enabled skill with `tools.skill.load({ name })`. `[[tools.available.search:server-name]]` requests discovering that MCP server's tools with `tools.available.search({ namespace: "mcp", query: "server-name" })`; follow continuation pages as needed, retrieve relevant contracts with `tools.available.get`, then call the appropriate tools. A mention does not bypass contract retrieval, permissions, or MCP connection requirements. If the server is unavailable, report that rather than substituting another server.

For exact source/Markdown/patch text containing backticks or quotes, supply `payloads` on the outer `exec` request and reference `payloads.<key>` within the program. Never minify human-authored code merely to save tokens. Before patching, read each exact source region; after a failure reread and rebuild. For terminal work, retain the returned `session_id` and continue that session instead of restarting the command. Plan Mode can create one plan and patch only the active plan, never source files.
