# Architecture

Model-facing AI browser screenshots (2026-10-28): `agentScreenshotCursor.ts` composites the last known AI pointer into the PNG supplied by browser.read and the `read` steps of browser.interact, without changing the Chromium document or the raw UI preview. The overlay uses Electron built-in `nativeImage` bitmap operations, not a native npm addon such as `sharp`, because unpackaged native binaries can crash the installed Windows main process during startup. The capture preserves actual viewport resolution. Single interactions and sequences report viewport width/height. `agentPageInput.ts` shares paced, distance-based input interpolation between drag and stroke, with bounded steps and a mouse release at the last completed location on errors; cancellation attempts a debugger-level release if the scoped protocol budget is aborted. Existing Code Mode contract caching is unchanged; Agent Mode and exec instructions discourage redundant contract retrieval across turns.


Live AI browser preview (2026-10-27): `agentLivePreview.ts` listens for Electron offscreen paint frames. An owner-checked IPC subscription from the selected `BrowserAgentPreview` enables throttled, JPEG-compressed frames (at most 10/s, bounded dimensions/bytes), independent of the model's explicit full-resolution `browser.read`. Unselected/closed panels stop publishing and reduce offscreen frame rate; tab destruction cancels pending work. `agentBrowserHost.ts` avoids redundant post-action screenshots while live preview is active. `browser.interact` supports connected `stroke` paths of 2–256 points with one press and one release, including release on input failure; user-owned tabs remain read-only. Browser navigation timeouts report observed URL/loading status rather than implying no navigation occurred.

AI browser tab inventory (2026-10-27): The Electron agent-tab registry is authoritative. Workspace UI fetches live AI-owned tabs through the owner-restricted `browser:listOpenAgentTabs` IPC on panel activation/project change, while `browser:openAgentTab`, `browser:agentFrame`, and `browser:terminateAgentTab` update visible tabs. Closing AI tabs waits for the backend termination event before removal; terminated IDs are guarded against late frame events. User-owned UI tabs remain local.

Browser viewport and sequence reliability (2026-10-27): `tools.browser.read` never takes width/height and the browser host always captures the existing tab viewport. `browser.open` sets an AI tab's viewport. Browser sequences accept `ms` as an alias of `duration_ms` for wait steps, rejecting both together. Coordinates remain independent of observation IDs. Tool instructions distinguish `tools.read({path})` from `tools.browser.read({tab_id})`.

Browser coordinate input (2026-10-27): `browser.interact` mouse coordinate actions, including drag and sequences, accept viewport x/y without an observation ID or a prior `browser.read`. Runtime viewport boundary validation and user-owned tab restrictions remain. `browser.read` can still supply observational data for visual targeting, but it is optional.

## Durable memory and compaction

Current implementation (updated 2026-10-20): compaction reconciles each conversation's existing `ConversationMemory` Markdown, previous continuation handoff, and evicted messages in one model call, then generates its short continuation handoff in a separate call using the updated memory. Both workers receive the same active/settled runtime meaning, bounded latest user intent, and transcript-visibility explanation through `compaction/turnContext.ts`. Their transcript covers the compacted source; recent retained messages may contain newer state. Both outputs are persisted together on the conversation's canonical `compaction_committed` event. Runtime replay injects a short instruction to read `@chat/DURABLE.md` instead of the memory contents. `tools.read` resolves that read-only alias exclusively through the current conversation ID and the latest valid memory on its active branch. Canonical history lives under the user's home `.tidecode/history/canonical-history/<conversationId>.json`, outside the project.

The continuation contains consolidated working state rather than an automatically appended prompt ledger. Historical intent remains bounded packet metadata (at most 1,000 estimated tokens, further limited by the retention target), and stored completion labels carry no authority. Runtime activity is distinct from task success; active compaction appends a continuation guard that preserves completed substeps and remaining response/work obligations. Recent history retention uses a token target and safe tool boundaries rather than a fixed message count. In-flight deduplication includes conversation ID when available, lifecycle, and the full input-message digest so different recent context cannot share a result.

`compaction/toolEvidence.ts` projects tool results for both workers before transcript serialization. For exec it extracts nested outcomes from structured metadata or the readable JSON-return/ToolResult-body format, preserving operation status, state, exit code, session, available command/subject, partial-output flags and bounded body excerpts. Each batch retains up to 100 outcomes within a 24,000-character budget; generic output uses a 2,000-character head/tail projection. This prevents large reads at the beginning of a batch from hiding later validation. Receipt extraction uses the same evidence reader and bounds carry-forward receipts to favor newer evidence. Unknown outer status remains unknown; successful API invocation does not imply process or task success. The stored history is not rewritten by this projection.

The host selects `INITIALIZE` when no previous `ConversationMemory` is supplied and `RECONCILE` when saved memory exists, including a saved empty-information placeholder. `prompts/durableMemory/index.ts` loads and separately caches `workers/durable-memory-initialize.md` and `workers/durable-memory-reconcile.md`; each API call receives only its selected complete instruction file. Initialization establishes the baseline from available evidence; reconciliation preserves applicable baseline knowledge and applies supported updates. The active tab passes its project root through `useBrowserPageActions.ts`. `electron/browser/screenshots.ts` creates `~/.tidecode/browser-screenshots/` under the user home, rejects redirected screenshot folders, and writes uniquely named PNGs without overwriting. Main-process screenshot actions validate the workspace sender and restrict clipboard/reveal operations to existing browser screenshot files in that folder. Saving does not modify the clipboard; Copy image reads the saved PNG. Capture/save failures appear beside the camera, while action errors remain in the toast.


## Incognito browser sessions

The new-tab dropdown offers normal and incognito tabs. Normal guests use `persist:tidecode-browser`. `electron/browser/sessions.ts` creates a unique nonpersistent partition per workspace-window/project private session, with HTTP caching disabled. Native tab tokens retain the session even for empty incognito tabs. Closing one private tab preserves the session for its siblings; closing the last token revokes access, waits for attached guests to be destroyed, then clears storage, cache, and connections. Renderer reload/crash and owner destruction revoke private sessions as well.

`BrowserTab` carries its mode and partition. `BrowserPanel.tsx` releases private tab tokens on close/unmount, skips private visit/favicon history writes, and passes no recent-site shortcuts to private new tabs. Only normal guests enter the shared favicon cache. Private tabs show an incognito indicator and cannot save screenshots, enforced in both the renderer and native capture handler. Menu cookie/cache clearing validates the active partition against its window owner, including on empty tabs. Floating DevTools and page zoom continue to target the owned guest.

Edited-send presentation suppresses the history-cutoff scroll anchor while an optimistic edited message is visible. The existing explicit follow-latest signal can therefore anchor the submitted edit at the bottom without the edit/revert anchor pausing following again.

Sidebar Chats selection (2026-10-24): `ProjectThreadSelector.tsx` adds the built-in Chats entry locally alongside project options, while `SidebarHistoryFilter.tsx` exposes All projects and available Archived history. Chats retains the existing unassigned-conversation filter and has no project mutation actions. Its directory subtitle uses the parent of the host-provided `getDraftAgentContextPathSync()` path; the remote bridge supplies the desktop host path as well.
